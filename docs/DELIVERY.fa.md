این نسخه را تا تکمیل ستون محیط واقعی، محصول آنلاین تکمیل‌شده تلقی نکنید. صفحهٔ ورود در نبود تنظیمات معتبر صریحاً اتصال تنظیم‌نشده را نشان می‌دهد.

## قابلیت‌های موجود

- سه پنل ایران، آمریکا و مدیر؛ نقش تماشاچی با محدودیت سمت سرور.
- حساب نام کاربری/رمز از طریق Supabase Auth، ساخت امن مدیر و کاربران، تغییر اجباری رمز اولیه، بازیابی و خروج.
- چند مسابقه، عضویت تیمی، شروع زمان‌دار، توقف/ادامه، پایان، آرشیو و ساخت سناریو با قوانین قبلی.
- سازه، سلامت، سطح، ثبت/ویرایش، غیرفعال‌سازی، هدف شناسایی‌شده/نامشخص/مخفی و شخصیت داستانی.
- مأموریت اتمیک، درخواست یکتا، قفل واحد، منابع غیرمنفی، دفاع احتمالاتی، رادارگریز اختصاصی آمریکا و دفاع دستی.
- تعمیر سروری برای سازه و جنگنده، بازیابی انرژی، ظرفیت هم‌زمان و دفتر منابع.
- اعلان با مخاطب مجاز، رسید خواندن به تفکیک کاربر، صدای اختیاری، تاریخچه، بازپخش، نمودار و چاپ نتیجه.
- تنظیم قوانین و منابع، مدیریت حساب و عضویت، واحدهای هوایی، نوع سازه، شخصیت، پیام عمومی، نگهداری و Audit Log.
- خروجی مجاز رویدادها و گزارش‌ها، پشتیبان منطقی کامل دادهٔ یک مسابقه، بازنشانی محافظت‌شدهٔ سناریوی آزمایشی.

## Backend

سه migration نسخه‌دار، ۲۵ جدول عمومی با RLS و یک جدول داخلی محدودیت تلاش ورود وجود دارند. UUID، FK، constraint، index، زمان سرور و محدودیت عملیات فعال تعریف شده‌اند. جزئیات در `ARCHITECTURE.fa.md` است.

| Edge Function  | کاربرد                                             | اجرا در محیط مقصد |
| -------------- | -------------------------------------------------- | ----------------- |
| `auth-session` | ورود با نام کاربری و بازیابی بدون افشای ایمیل      | منتشر نشده        |
| `game-command` | اعتبار JWT و عبور فرمان به تراکنش معتبر PostgreSQL | منتشر نشده        |
| `admin-users`  | ساخت امن کاربر و ارسال بازیابی توسط مدیر           | منتشر نشده        |
| `engine-tick`  | ورودی جایگزین برای زمان‌بند خارجی با راز اختصاصی   | منتشر نشده        |

موتور امتیاز، دفاع و آسیب، اقتصاد، تعمیر و مجوزهای نهایی داخل PostgreSQL اجرا می‌شوند. هیچ تصمیم معتبر بازی در localStorage، Zustand یا انیمیشن گرفته نمی‌شود.

## نتایج آزمون

- `npm run build`: موفق، همراه با بررسی سخت‌گیرانهٔ TypeScript.
- `npm test`: ۹ آزمون در ۳ فایل موفق.
- `npm run test:db`: ۳۸ آزمون PostgreSQL موفق.
- `npm run test:edge`: بررسی Deno برای هر چهار Edge Function موفق.
- `node scripts/check-public-build.mjs`: کلید server/secret در خروجی عمومی پیدا نشد.

آزمون PostgreSQL شامل نصب migrations، عضویت، مخفی‌سازی مختصات، RLS مستقیم، منع دستکاری منابع و نقش، ثبت اتمیک مأموریت، تکرار درخواست، قفل جنگنده، محدودیت تعمیر، رادارگریز، دفاع دستی، کسر منابع، پردازش بدون مرورگر، توقف/ادامه، نقش spectator، تعلیق حساب، زمان‌بندی، تغییر hash رمز، عدم دسترسی به توابع داخلی، نتیجه و پشتیبان است.

PGlite یک موتور PostgreSQL محلی است؛ Auth و `auth.uid()` در harness حداقلی شبیه‌سازی شده‌اند. بنابراین ورود واقعی، ارسال ایمیل، Realtime شبکه‌ای، فشار هم‌زمان روی چند اتصال PostgreSQL و E2E دو مرورگر تأییدشده نیستند. اسکریپت آزمون زنده و فهرست پذیرش برای تکمیل آن‌ها آماده‌اند.

سرویس preview محیط در دسترس نبود: `sites-previewd mailbox is unavailable`. به همین دلیل screenshot و آزمون بصری موفق ادعا نمی‌شوند.

## حساب‌های اولیه

هیچ حساب واقعی یا رمز ثابتی در این تحویل ایجاد نشده است. ابتدا migrations روی پروژهٔ منتخب اجرا شوند؛ سپس اولین مدیر با `scripts/bootstrap.mjs` از محیط امن ساخته شود. کاربران دو تیم از پنل مدیر ایجاد و عضو مسابقه شوند. plaintext رمز فقط یک بار تحویل داده می‌شود و در دیتابیس بازی ذخیره نمی‌شود. بدون ایمیل ثبت‌شده، بازیابی ایمیلی ممکن نیست.

## موارد باقی‌مانده

۱. شناسهٔ پروژهٔ اختصاصی Supabase یا سازمان مقصد برای ساخت پروژه لازم است. پروژهٔ آموزشی موجود بدون انتخاب کاربر تغییر داده نشده است.
۲. اعمال migrations، استقرار Edge Functions، کنترل Advisors، فعال‌بودن Cron، تنظیم Auth/SMTP و ثبت متغیرهای عمومی Frontend.
۳. انتخاب GitHub Actions در Settings → Pages و بررسی deployment موفق. ابزار GitHub فعلی عملیات تنظیم Pages را ارائه نمی‌کند و مرورگر وارد حساب نشده است.
۴. اجرای `test:live` و فهرست پذیرش دو مرورگر، موبایل و دسکتاپ.
۵. ارزیابی بار و رفتار قفل مسابقه برای تعداد زیاد کاربر، سیاست نگهداری رویدادها و پشتیبان محیط مقصد.

موارد تکمیلی خارج از اجرای فعلی: بارگذاری تصویر/آواتار اختصاصی، رابط انگلیسی کامل و بازیابی خودکار یک فایل JSON دلخواه. زبان اصلی فارسی و آیکون‌های داخلی فعال‌اند. خروجی پشتیبان بازی جایگزین پشتیبان Auth نیست.

## ساختار تحویل

کد ویژگی‌ها در `src/features`، رادار و UI در `src/components`، قراردادها و داده در `src/lib`، ترجیحات در `src/stores`، migrations و Edge در `supabase`، آزمون‌ها و ابزارهای مدیریتی در `tests` و `scripts` و گردش انتشار در `.github/workflows/deploy.yml` قرار دارند.
