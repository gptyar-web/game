# پذیرش محیط منتشرشده

این فهرست برای اجرای پس از اتصال Supabase است. آماده‌بودن فهرست، به معنی انجام این آزمون‌ها روی محیط آنلاین نیست.

## آماده‌سازی

- migrations روی پروژهٔ اختصاصی اعمال شوند و Advisors امنیت و عملکرد بررسی شوند.
- signup خاموش، SMTP و Redirect URL تنظیم و چهار Edge Function منتشر شوند.
- Cron فعال و بدون خطا باشد. برای اطمینان، همهٔ پنل‌ها را ببندید و تکمیل تعمیر را از SELECT مستقیم بررسی کنید.
- مدیر و دو کاربر تیمی با رمز تصادفی ساخته شوند؛ رمز اولیه در اولین ورود تغییر کند.
- در دو پروفایل مرورگر مستقل وارد ایران و آمریکا شوید؛ تغییر team در devtools نباید دادهٔ طرف مقابل را برگرداند.

## جریان اصلی

۱. مدیر یک مسابقهٔ آزمایشی مستقل بسازد، اعضا و قوانین را تعیین کند و مسابقه را شروع کند.
۲. هر تیم باید فقط دارایی‌های خود و contacts مجاز طرف دیگر را دریافت کند. درخواست مستقیم به جدول خام تیم مقابل باید خالی یا ممنوع باشد.
۳. نام کاربری درست/رمز نادرست، خروج، بازیابی ایمیلی، تعلیق حساب و ورود دوباره بررسی شوند. JWT قدیمی حساب تعلیق‌شده نباید دادهٔ مسابقه دریافت کند.
۴. یک سازهٔ ساختگی ثبت، روی رادار انتخاب، ویرایش، ارتقا و در صورت مجازبودن غیرفعال شود. جست‌وجو، فیلتر، مرتب‌سازی و صفحه‌بندی بررسی شوند.
۵. یک مأموریت با تأیید هزینه ثبت شود؛ منابع پیش از شروع کم شوند. همان request ID را هم‌زمان دوباره بفرستید؛ یک مأموریت و یک کسر منابع باید ایجاد شود.
۶. جنگندهٔ رزروشده، هدف مخفی، منابع ناکافی، بازی متوقف و کاربر تماشاچی باید رد شوند.
۷. آمریکا مأموریت رادارگریز اجرا کند. پاسخ‌های ایران، payload رویدادها، HTML و داده‌های Realtime نباید مختصات آن را داشته باشند. دفاع دستی فقط یک بار در زمان اختلال مجاز باشد.
۸. آسیب و امتیاز در هر دو پنل بدون reload نمایش داده شود. تعمیر را شروع کنید، مرورگر را ببندید و پس از زمان کافی برگردید؛ وضعیت باید از سرور تکمیل شده باشد.
۹. شبکه را قطع و وصل کنید. وضعیت اتصال و بازیابی داده کنترل شود. retry درخواست نباید هزینه یا رویداد تکراری بسازد.
۱۰. مسابقه را متوقف و ادامه دهید؛ تایمرها نباید در زمان توقف پیش بروند. مسابقه پایان یابد، گزارش و Replay بررسی و نتیجه چاپ شود.
۱۱. Reset فقط همان سناریوی test را تغییر دهد؛ مسابقهٔ اصلی و سایر مسابقات باقی بمانند.

## نمایش و دسترس‌پذیری

- عرض‌های ۳۶۰، ۷۶۸ و ۱۴۴۰ پیکسل؛ منوی موبایل، جدول اسکرول‌شونده و رادار بررسی شوند.
- ترتیب Tab، عنوان فرم‌ها، focus modal، خطاها، tooltip و وضعیت دکمه‌های نامجاز بررسی شوند.
- کاهش افکت‌ها، صدای اختیاری، اعلان خوانده‌شده و شمارندهٔ پیام‌ها بررسی شوند.
- Console و درخواست‌های ناموفق مرورگر بررسی شوند.
- نشانی `.../game/#/radar` با refresh مستقیم باید باز شود.

## آزمون خودکار زنده

`npm run test:live` ورودی JSON محرمانه را از stdin می‌خواند و یک مسابقهٔ test مستقل ایجاد می‌کند. بعد از موفقیت آن را پایان می‌دهد و آرشیو می‌کند. خطا را با شناسهٔ مسابقه گزارش می‌دهد و هیچ مسابقهٔ موجودی را reset نمی‌کند. این آزمون دو کلاینت Supabase را بررسی می‌کند؛ آزمون بصری دو مرورگر همچنان جداگانه است.
